# Hotel Service – JWT Token Verification

This Spring Boot microservice stores and returns hotel details. Every `/hotels/**`
endpoint requires a valid JWT signed with **HS256**.

## Requirements

- JDK 25
- Maven 3.9+
- PostgreSQL
- Eureka Server at `http://localhost:9000/eureka/` (or change `EUREKA_URL`)

## 1. Create the database

In PostgreSQL, run:

```sql
CREATE DATABASE hoteldb;
```

## 2. Configure environment variables

Set these before starting the application:

- `DB_PASSWORD`: PostgreSQL password
- `JWT_SECRET`: Base64-encoded secret that is exactly the same key used by
  the User Service to sign HS256 tokens
- Optional `DB_URL`, `DB_USERNAME`, and `EUREKA_URL`

Generate a suitable random secret (32 bytes or more) with:

```bash
openssl rand -base64 32
```

Use the generated value as `JWT_SECRET` in both User Service and Hotel Service.
Do not commit the secret to Git or share it publicly. If the User Service uses
RS256 instead of HS256, this decoder must be changed to use the matching public key.

## 3. Run the service

From this folder:

```bash
mvn spring-boot:run
```

The service starts on port `8084`.

## 4. Test with Postman

Direct service URL:

- `GET http://localhost:8084/hotels`
- `GET http://localhost:8084/hotels/1`
- `POST http://localhost:8084/hotels`

For each request, choose **Authorization → Bearer Token** and paste a JWT
generated by the User Service.

Example POST body:

```json
{
  "hotelName": "Starlight Resort",
  "location": "Vijayawada",
  "address": "Main Road",
  "description": "Luxury Resort",
  "contactNumber": "9876543210",
  "rating": 4.5
}
```

Expected results:

- Valid token: request proceeds (usually `200 OK`; POST usually `200 OK`)
- Missing, invalid, expired, or incorrectly signed token: `401 Unauthorized`
- Unknown hotel ID: `404 Not Found`

## 5. API Gateway route

For a Spring Cloud Gateway WebFlux gateway using the property style from the
existing project, add the route below to the Gateway `application.properties`:

```properties
spring.cloud.gateway.server.webflux.routes[0].id=hotel-service
spring.cloud.gateway.server.webflux.routes[0].uri=lb://hotelservice
spring.cloud.gateway.server.webflux.routes[0].predicates[0]=Path=/hotelservice/**
spring.cloud.gateway.server.webflux.routes[0].filters[0]=StripPrefix=1
```

Then call:

```text
GET http://localhost:8080/hotelservice/hotels
```

The gateway must forward the `Authorization: Bearer <token>` header. This
project secures the Hotel Service itself, so token verification still occurs
even if a request reaches port 8084 directly.

## Notes

- This is the Hotel Service project only; it does not include User Service
  token-generation code or the API Gateway project.
- The JWT decoder validates the HS256 signature and token timestamps when
  present. Make sure the User Service includes an `exp` claim.
- The sample controller allows any authenticated user to read and add hotels.
  Add role-based authorization if only admins should create hotel records.
